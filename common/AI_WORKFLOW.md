# AI_WORKFLOW

AIがPEAKHEADZ製品を変更する時の共通作業姿勢です。所有者の意思を代替する規則ではありません。菊田の明示指示、法令、安全、外部サービスの必須制約を優先します。

## 基本姿勢

- 正本に答えがある内容を利用者へ再確認しない。
- 安全で可逆な判断により依頼範囲内で進められる時は、不要に停止しない。
- 存在しない制約やブロッカーを作らない。
- 依頼範囲を勝手に縮小せず、勝手に拡大しない。
- 一つの問題を見つけても、成立する残りの作業を放棄しない。
- 同じ確認を繰り返さない。
- AIの判断だけで品質を保証せず、可能な確認は検査・テストへ移す。

## 既存尊重

DEFAULTは次の通りです。

- 既存完成版と現在正常な挙動を優先する。
- 必要最小限の差分で要求を満たす。
- 全面書き換え、目的外のリファクタリング、依存追加、新規ファイル作成をしない。
- 依頼と関係のない「ついで修正」をしない。
- 未commit変更、既存成果物、設定、予約を勝手に戻したり削除したりしない。

## 正本と派生物

- GitHub repositoryを正本の置き場所とする。
- 共通仕様と共通Pythonツールの正本は `peakheadz-standards` とし、製品へ複製しない。
- 製品固有事項は製品の `ORIGINAL.md` 等に置く。
- `AI_CONTEXT.md` は定めた正本見出しから生成し、直接編集しない。
- 正本Markdown全文の単純連結をAI contextにしない。

## 外部接続とPreflight

作業前に外部サービスが必要な場合のみ、最小限の事前確認（preflight）を行います。

- 依頼受領 → 必要な正本を読む → 外部サービスの要否を判定 → 必要な検査のみ実行 → 作業。
- 外部サービス（GitHub、Cloudflare等）を使用しない作業では、その認証確認を行いません。
- 開発環境および外部接続の詳細は `common/DEVELOPMENT_ENVIRONMENT.md` を正本とします。
- 外部接続やコマンドが失敗した場合、以下の区分で原因を特定し、同一の失敗コマンドを無目的に繰り返しません。
  - `AUTH`: トークン期限切れ、未ログイン
  - `PERMISSION`: アクセス権限不足、Git dubious ownership
  - `NETWORK`: 接続タイムアウト、オフライン
  - `TOOL_MISSING`: CLIコマンドの未インストール・PATH未通
  - `CONFIG`: 設定不整合、環境変数競合
- 1つの経路で失敗した際に、合意のない別トークン探索や無秩序なプロトコル変更を行いません。

## 完了条件

依頼に応じて、次のうち必要なものを終えたら停止します。

- 実装
- 変更に必要なテスト
- 適用profileのquality check
- 変更した事実に対応する正本更新
- 元情報を変更した場合のAI context再生成とstale check

未依頼の改善、出荷、配布、販売、Web実証へ自発的に進みません。
